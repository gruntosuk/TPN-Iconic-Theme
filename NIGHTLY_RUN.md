# Iconic TPN - nightly run (3 systems, up to 5 if going well)

Scheduled task brief. Each night, finish THREE systems to the agreed standard. If those three went well (no more than one regeneration each, no blockers, usage and time left), carry on and finish up to FIVE systems in total (user request 2026-10-07); do one full set of records, zip and NAS sync at the end covering all of them, but write the log entry and sync after the third system as a safety net. If anything goes wrong, stop at the last finished system and log how far you got. Then write a report. Order and popularity do not matter.

## Locations
- Working theme: ~/tpn-build/iconic-tpn (scripts in _tools, python env ~/tpn-build/venv)
- To-do list: iconic-tpn/TODO.md (generated by ~/tpn-build/make_todo.py)
- Prompt sheet: iconic-tpn/PROMPTS.md
- NAS project: /Volumes/stuff/Emulation/TPN Iconic Theme (zip, mockups, sources, TODO/PROMPTS/CREDITS copies)
- PixN themes for logos/hardware: /Volumes/stuff/Emulation/TPN Iconic Theme/Retrobat/.emulationstation/themes (Carbon-PixN/art/logos, Carbon-PixN/art/consoles, ckau-book-PixN, Hypermax-Plus-PixN)
- Style reference: https://raw.githubusercontent.com/Delgan/iconic-es/main/_inc/backgrounds/snes.webp


## Access fallbacks (read first)
- PixN logos/hardware: use ~/tpn-build/pixn_assets/carbon/(logos|consoles) and ~/tpn-build/pixn_assets/ckau/(logos|consoles) - local copies, no NAS needed.
- Gemini downloads: Chrome saves to ~/Downloads. If Downloads is not accessible, find the file via Chrome's downloads page, or set Chrome's download location to ~/tpn-build/incoming. Move finished downloads into ~/tpn-build/incoming before processing.
- NAS (/Volumes/stuff/...): if not mounted or not accessible, do everything locally (theme, mockups in ~/tpn-build/mockups, originals in ~/tpn-build/sources/<code>/, zip in ~/tpn-build) and add NAS SYNC PENDING to NIGHTLY_LOG.md with the list of files to copy. Never stop the run just because the NAS is missing.

## 1. Pick 3 systems (up to 5)
Take any 3 unticked systems from TODO.md sections B1, C, D or E.

## 2. For each system
1. Research its real games (web search). Pick one game ORIGINAL to that machine. Fan-art style is fine (updated 2026-10-05), but NEVER use a famous character or mascot on any system other than its own (no Samus on anything but Nintendo, no Mario/Sonic elsewhere, etc.). Use original characters instead. Gemini often copies the hero from the style reference (the SNES reference is Super Metroid), so check every background for this.
2. Background (Gemini in Chrome, NEW chat per image): attach the SNES style reference (open it in a tab, screenshot, upload_image to Gemini's file input), paste the STANDARD BLOCK from PROMPTS.md with your scene. Check: one large hero centre-right, left third dark/quiet, calm bottom, no text/logos/UI/number plates. Fix with small follow-up requests in the same chat. Download full size (never screenshots, never upscale).
3. System image:
   - Arcade boards (UPDATED 2026-10-08, agreed with the user): the system image is a tight THREE-CABINET GROUP in the style of the OG theme's cps2 image (OG file: iconic-es-main/_inc/controllers/cps2.webp on the NAS; also arcade, atomiswave, naomi, triforce). Base the cabinets on the machine used for the system's MOST FAMOUS game. Upright cabinets: CENTRE = the system's own branded cabinet in full bright colour, facing the camera, in front, with the system logo on the marquee and lower front and a boot screen showing the system logo; LEFT and RIGHT = two real, well-known games of that system, black-bodied cabinets with slightly faded/muted colours, each with its own full-height side vinyl, own marquee text and gameplay on screen, standing slightly behind the centre one, turned about 30 degrees outward, overlapping behind its edges, side panels touching, NO gaps. Sit-down/deluxe boards (Ringwide, Sega Nu, segaalls, segare, segaer etc.) keep a single sit-down cabinet and are NOT turned into groups. Gemini workflow: attach (1) the OG cps2 image on light grey as layout reference, (2) the existing cabinet on light grey (shape), (3) the system logo, (4) the background; green (#00FF00) background, no shadow, hard clean edges; cut out with _tools/cutout_green.py. Reference prompt that worked (segasystem32): see PROMPTS.md "Arcade three-cabinet groups". Always confirm the downloaded file is NEW (check ~/Downloads timestamps) before cutting out.
   - Computers: flat TOP-DOWN overhead view. If no clean photo, Gemini top-down render from a reference photo (PixN consoles folder or web), green background, no shadow.
   - Consoles/handhelds: a clean photo or Gemini render on green.
   - Verify identity - PixN files are sometimes mislabelled (e.g. an Apogee logo that was really the Elektronika BK).
4. Logo: PixN Carbon logos first (system32.png style PNGs are usually best; SVG renders via qlmanage often come out cropped - check). If nothing usable, make a wordmark in the house style (Arial Black; machine name in its case colour, model number white on a block). Run _tools/make_logo.py (sticker border + 540x110 canvas).
5. Cut-outs: _tools/cutout_green.py for green-screen images (trims dark bars, removes olive fringe), _tools/cutout_flat.py for plain white/grey photos.
6. Install into iconic-tpn/_inc/backgrounds|controllers|logos/<code>.webp (back up old ones to ~/tpn-build/replaced, delete any overlays/<code>.webp). Fix wrong metadata years if spotted.
7. Render the mockup (mockup.py, set the for-loop to the system), view it in Chrome via the local server (python3 -m http.server 8765 --bind 127.0.0.1 in /tmp/tpnview) and zoom on the cabinet edges for green fringe / bad cut-outs. Redo anything that fails.

## 3. Record
- Move originals to NAS sources/<code>/ ; copy mockup to NAS TPN Iconic/mockups/

## 4. Report
Append to NIGHTLY_LOG.md (theme folder, copy to NAS): date, the 3-5 systems, game chosen for each, anything redone and why, anything you were unsure about for the user to review. If you hit a usage limit or a blocker, log how far you got so the next run can continue.

## Background composition rules (added 2026-10-05, from user review)
- The system-name column covers roughly the LEFT 40-45% of the frame in the theme. Keep ALL focal subjects (characters, creatures, the main action) in the RIGHT 55%; the left side should be empty atmosphere only. Check the mockup for this before delivering.
- Action must be coherent: if a character shoots something, the projectile must be one continuous line from the weapon to the target, the target clearly visible and not hidden by effects, and nothing else behind the shooter.
- Rear/over-the-shoulder views of ORIGINAL characters are fine and welcome for variety.
- Always review the rendered mockup yourself against these rules and regenerate before showing the user.
- HARD RULE (user, 2026-10-05): NOTHING may ever sit in the system column area (left ~45%% of the frame): no characters, limbs, wings, bolts or effects. Verify on the mockup; if any part overlaps the column, regenerate. One single character only, never a duplicated or cropped second figure.
